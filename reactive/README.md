# reactive

Пакет `reactive` предоставляет небольшую generic-систему реактивных значений для Go. Он помогает хранить состояние, подписывать код на изменения и собирать производные значения без ручной передачи обновлений между компонентами.

## Основные понятия

### Signal

`Signal[T]` хранит изменяемое значение типа `T`.

- `NewSignal(name, value)` создаёт сигнал и регистрирует его по имени.
- `Get()` читает текущее значение.
- `Set(value)` заменяет значение и уведомляет подписчиков.
- `Update(func(T) T)` изменяет значение через функцию.
- `Subscribe(func(T))` получает новое значение.
- `SubscribeChan(bufferSize)` предоставляет канал обновлений.

Используйте `Signal`, когда значение меняется во времени и на эти изменения должны реагировать несколько частей программы: состояние формы, выбранный элемент, счётчик, настройки или текущий статус.

### Computed

`Computed[T]` хранит значение, вычисляемое из зависимостей. Он пересчитывается после уведомления любой зависимости.

```go
count := reactive.NewSignal("count", 1)
double := reactive.NewComputed(
    func() int { return count.Get() * 2 },
    count,
)

subscription := double.Subscribe(func(value int) {
    fmt.Println("double:", value)
})
defer subscription.Unsubscribe()

count.Set(3) // печатает: double: 6
```

Используйте `Computed`, когда значение полностью определяется другими реактивными значениями. Для независимого побочного действия используйте `Effect`, а не `Computed`.

### Effect и подписки

`Effect` выполняет функцию при изменении `Signal`. `SubscribeEffect` позволяет подписаться без использования нового значения.

```go
stop := count.Effect(func(value int) {
    fmt.Println("count changed:", value)
})
defer stop.Unsubscribe()

refresh := count.SubscribeEffect(func() {
    fmt.Println("refresh needed")
})
defer refresh.Unsubscribe()
```

Подписки нужно сохранять и отменять через `Unsubscribe`, когда владелец состояния больше не используется. Пользовательские callbacks вызываются вне mutex, поэтому внутри callback можно безопасно читать или изменять другие реактивные значения.

### Event

`Event[T]` предназначен для одноразовых сообщений, а не для хранения состояния.

```go
clicked := reactive.NewEvent[string]()
clicked.Subscribe(func(button string) {
    fmt.Println("clicked:", button)
})
clicked.Emit("save")
```

Выбирайте `Event`, когда важен сам факт события: нажатие кнопки, команда или уведомление. Если новым подписчикам нужно получить текущее значение, используйте `Signal`.

### Batch

`Batch` группирует уведомления до завершения внешнего блока. Вложенные вызовы поддерживаются.

```go
reactive.Batch(func() {
    count.Set(2)
    reactive.Batch(func() {
        count.Set(3)
    })
    // callbacks выполняются после завершения внешнего Batch
})
```

Используйте `Batch`, когда несколько связанных значений меняются одной операцией и промежуточные уведомления не нужны.

## Вспомогательные инструменты

| API | Назначение | Когда использовать |
| --- | --- | --- |
| `Memo[T]` / `NewMemo` | Ленивое вычисление один раз | Дорогое значение, которое неизменно после первого чтения |
| `Debounce` | Передаёт только значение после паузы | Поиск по вводу, автосохранение, resize |
| `Throttle` | Ограничивает частоту обновлений | Scroll, mouse move, частые внешние события |
| `Persist` | Связывает `Signal` с `Storage` | Настройки и состояние, которое нужно восстановить |
| `FileStorage` | JSON-хранилище на диске | Простое локальное хранение без отдельной БД |
| `Undoable[T]` | История изменений с `Undo` и `Redo` | Редакторы, формы и действия, которые можно отменить |
| `Animate` | Плавно меняет `Signal[float64]` | Прогресс, числовые параметры интерфейса и переходы |
| `List[T]` | Потокобезопасный список с подписками | Коллекции, изменения которых должны отображаться в UI |

Пример debounce и persistence:

```go
storage := reactive.NewFileStorage("settings.json")
query := reactive.Persist(storage, "query", "")
settledQuery := reactive.Debounce(query, 300*time.Millisecond)

settledQuery.Subscribe(func(value string) {
    fmt.Println("search:", value)
})
```

## Как выбрать API

- Нужно хранить текущее состояние: `Signal`.
- Нужно вывести состояние из других сигналов: `Computed`.
- Нужно выполнить действие при изменении: `Effect` или `Subscribe`.
- Нужно передать сообщение без текущего состояния: `Event`.
- Нужно собрать несколько изменений в одно действие: `Batch`.
- Нужно ограничить поток обновлений: `Debounce` или `Throttle`.
- Нужно сохранить историю: `Undoable`.
- Нужно восстановить значение между запусками: `Persist`.

## Особенности

- Все основные типы используют generics: `Signal[T]`, `Computed[T]`, `Event[T]`, `List[T]` и `Undoable[T]`.
- `Get` и операции подписки защищены mutex; callbacks выполняются после освобождения mutex.
- Обновления выполняются синхронно, если не используются таймеры или `Animate`.
- `SubscribeChan` использует неблокирующую отправку: если буфер заполнен, обновление пропускается.
- Зависимости `Computed` передаются явно. Пакет не отслеживает автоматически вызовы `Get()` внутри функции вычисления.

    Поэтому каждый сигнал, от которого зависит вычисление, нужно указать вторым и последующими аргументами `NewComputed`:

    ```go
    count := reactive.NewSignal("count", 1)
    step := reactive.NewSignal("step", 2)

    total := reactive.NewComputed(
            func() int { return count.Get() * step.Get() },
            count, step,
    )
    ```

    Если передать только `count`, `total` будет пересчитываться после изменения `count`, но не после изменения `step`. Если не передать зависимости вообще, вычисление выполнится при создании `Computed`, но последующие изменения сигналов не вызовут пересчёт.
